# Проверка E Voice 1.1.1

**19 ноября 2026.** Семь установочных и переносимых пакетов собраны из коммита `a41d25c`. Каждый содержит интерпретатор, движок и русскую модель. Во всех пяти нативных сборках выпуск распознал контрольную речь с отключённой сетью. Тот же Windows EXE отдельно прошёл проверку совместимости на Windows 11 ARM. [Сборка и протоколы на GitHub](https://github.com/moldset-mmc/e-voice/actions/runs/44522090141) · [Машиночитаемые результаты](https://github.com/moldset-mmc/e-voice/releases/download/v1.1.1/QA-v1.1.1.json)

## Что исправлено при аудите

В 1.1.1 проверка вставки использует стандартное поле Win32 на чистой Windows-машине. Она ставит текстовый курсор в середину строки, вводит русскую фразу и сверяет исходное содержимое буфера обмена. Проверочный редактор работает только в одноразовой виртуальной машине CI.

| Участок | Обнаруженное поведение | Исправление и проверка |
| --- | --- | --- |
| Вставка диктовки | За время распознавания фокус мог перейти в другой редактор, и готовая фраза предназначалась уже другому окну. | В Windows сохраняются HWND и PID при остановке записи. Перед вводом проверяется активное окно. Новая запись отменяет отложенную вставку предыдущей. Последняя фраза доступна для копирования. Есть отдельные тесты на смену окна и задержку из-за модификатора. |
| Настройки и кнопка | При запуске настройка скрытой кнопки и сохранённая позиция переопределялись. Повреждённый JSON мог сорвать запуск. | Видимость и положение восстанавливаются с учётом экрана. Поддерживаемые поля проверяются по типу. Запись настроек использует временный файл и атомарную замену. |
| Микрофоны и память | Устройство должно было поддерживать 16 кГц. Последний аудиоблок выходил за лимит длительности. Длинный WAV целиком копировался в память. | При необходимости используется штатная частота устройства с ресэмплингом в движке. Лимит составляет ровно 10 минут. WAV читается частями, до 20 секунд с одним отсчётом для поиска точки разделения. Проверены совпадение границ с микрофонным режимом и реальная речь при 16 и 48 кГц. |
| Установка на другом компьютере | Комплект зависел от устройства Windows и старого расположения Tcl/Tk. macOS Installer мог выбрать ранее найденную копию приложения. | Проверяется запуск установленного экземпляра. Учтены Tcl/Tk с данными в DLL. Путь Mac-пакета закреплён за папкой «Программы» текущего пользователя. Для Linux проверены DEB и повторная установка архива в домашнюю папку с пробелом в имени. |
| Поставка и зависимости | В прежнем репозитории отсутствовала лицензия авторского кода. Копирование всей рабочей папки модели допускало случайные файлы. PyPI указывал исправления безопасности для используемой Pillow 12.3.0. | Добавлены MIT для E Voice и отдельные уведомления компонентов. Для модели упаковщик разрешает только четыре файла из закреплённого манифеста, сам манифест и лицензию. Проверяются размеры и SHA-256. Pillow обновлена до 13.0.0. Для всех 26 пакетов из lock-файла проверен индекс уведомлений PyPI на дату аудита, активных записей для этих версий не найдено. |

Проверка исходников охватила обработку аудио, отдельный процесс распознавания, хранение настроек, системный ввод, мышь, плавающую кнопку, всплывающие окна, конфигурацию сборки и сценарии установки. Код E Voice не отправляет микрофонные записи во внешний сервис. При штатной диктовке аудио и последний результат находятся в оперативной памяти. На macOS и X11 результат для автовставки помещается в системный буфер, поэтому срок его хранения зависит также от менеджера буфера пользователя. ## Скорость, оперативная память и размер

На Windows x64 в виртуальной машине GitHub измерялась задержка от **остановки записи до готового текста**. На вход подавалась одна секунда речи. Для холодных и тёплых измерений загрузка начиналась за секунду до остановки.

На чистой машине Windows команда установки из заранее скачанной папки заняла около **18 секунд** вместе с проверкой SHA-256. Это интервал между началом шага и сообщением об успешной установке. [Журнал Windows](https://github.com/moldset-mmc/e-voice/actions/runs/44522090141/job/135553029095)

| Состояние | Результат |
| --- | --- |
| Модель уже в памяти, три повтора | 173–175 мс, медиана 173 мс |
| Модель заново загружается с диска, три повтора | 924–1015 мс, медиана 964 мс |
| Начать и сразу остановить без времени на предзагрузку | 1985 мс в одном прогоне |
| Готовность до первой фразы | 52,5 МиБ рабочего набора |
| После распознавания с загруженной моделью | 362,5 МиБ суммарного рабочего набора интерфейса и распознавателя |
| После выгрузки модели через 30 секунд простоя | 59,9 МиБ рабочего набора |

Windows-установщик занимает 182 580 876 байт, около **183 МБ**. Четыре файла модели в распакованном виде занимают 231 897 202 байта. Установка копирует веса один раз. Повторная фраза в течение 30 секунд использует уже загруженную модель. На другом процессоре и диске время будет отличаться. [Размеры и SHA-256 всех пакетов](https://github.com/moldset-mmc/e-voice/releases/tag/v1.1.1)

## Границы выпуска

- Включена русская GigaAM v3. Другим языкам потребуется другая модель. Доли ошибок распознавания на корпусе речи в этом выпуске не измеряли.
- Целевые платформы — современные настольные ОС 64 бит. На Mac проверена версия 15. На Linux использованы glibc 2.35 и графическая сессия. Android, iOS, Windows 7/8 и 32-битные компьютеры потребуют отдельных портов или сборок.
- В Wayland результат доступен через системный буфер и обычную вставку. Глобальный перехват сочетаний и тройного щелчка реализован для X11. Работу с физическими микрофонами, разрешениями macOS и каждым оконным менеджером следует оценивать на целевом компьютере.
- Коммерческая подпись Windows и нотаризация Apple в этот выпуск не входят. Для распознавания в обычных приложениях используются разрешения текущего пользователя. Системные защищённые поля могут блокировать ввод. [Установка и разрешения](README.md#скачать)

## Оценка переноса на Rust

**Скорость.** На Windows x64 с Intel Core i9-10910 взяли первую секунду тестового WAV (16 кГц, моно) и подали её тем же путём, что и запись микрофона. После одного прогрева выполнили 20 вызовов `SpeechEngine.transcribe` с загруженной GigaAM и четырьмя потоками движка. В каждом вызове замерили общее время и время внутри `recognizer.decode_stream` через `perf_counter`. Во всех повторах получился один и тот же текст. [Тестовый WAV](tests/fixtures/russian-example.wav) · [Настройки движка](speech_engine.py)

| Где измеряли | Медиана |
| --- | --- |
| Обработка фразы внутри рабочего процесса | 66,7 мс |
| Вызов нативного декодера | 63,9 мс |
| Всё остальное внутри обработки той же фразы | 2,8 мс |

Медианная доля вызова декодера составила 95,8%. При тех же весах и движке на этом примере на оптимизацию остальной обработки внутри распознавателя приходится около 3 мс. Время ожидания модели и обмена с интерфейсом учитывает отдельный тест от остановки до готового текста. Уже получив текст, Windows-версия планирует первую попытку вставки через 80 мс и проверяет, осталось ли активным окно диктовки. [Сквозной тест](ui_checks.py) · [Вставка результата](app.py#L554-L580)

**Размер загрузки.** В Inno Setup собрали два контрольных пакета с параметрами выпуска `lzma2/normal` и `SolidCompression=yes`. Пакет без файлов занял 2 096 770 байт, с четырьмя файлами модели — 164 082 614 байт. Разница в 161 985 844 байта (162 МБ) эквивалентна примерно 89% от размера опубликованного EXE. Это оценка вклада модели при таком сжатии. В полный комплект также входят движок распознавания, интерфейс и установщик. [Файлы модели](models/gigaam-v3/manifest.json) · [Параметры упаковки](installer/EVoice.iss)

**Прогноз.** Нативный интерфейс на Rust потенциально уменьшит расход памяти до первой записи и ускорит запуск приложения. При сохранении модели и алгоритма ожидается сопоставимое качество текста и небольшой выигрыш внутри прогретого распознавателя. Разницу в полном времени до вставки, памяти и надёжности можно установить сравнением двух готовых приложений на одном компьютере. Приведённые замеры относятся к E Voice 1.1.1 на Python. [Примеры Rust от разработчиков sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx/tree/master/rust-api-examples)
